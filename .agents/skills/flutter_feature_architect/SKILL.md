# Flutter Feature Architect Standards

## 1. Архитектура и Структура
* Мы используем **Feature-Driven Architecture**. Каждый модуль живет в `lib/features/<имя_модуля>`.
* Внутри фичи строгое разделение: `view/` (UI), `bloc/` (состояние), `repository/` (сеть), `models/` (данные).

## 2. Баланс связности и лимитов файлов
* **Целевой лимит:** 200–250 строк. Жесткий потолок: 300 строк.
* **Принцип связности (Locality of Behavior):** Связанные BLoC (с эвентами и стейтами) и зависимые формы имеют право занимать до 300–350 строк, если их разделение разрушает контекст.
* **Табу на файлы-карлики:** Запрещено создавать файлы размером менее 60 строк (например, выносить отдельный стейт или одну кнопку). Вспомогательные приватные классы должны жить в конце родительского файла.
* **Критерий выноса:** Выносить код в отдельный файл ТОЛЬКО если компонент реально переиспользуется в 2+ местах, либо содержит самостоятельную логику (валидаторы, калькуляторы), либо файл приближается к 300 строкам. Никакого слепого механического распила.

## 3. Управление состоянием (BLoC)
* Запрещено использовать `StatefulWidget` для хранения бизнес-логики и походов в сеть.
* Вся логика выносится в BLoC. Используй пакет `equatable` для состояний.

## 4. Сеть и Данные
* UI и BLoC никогда не делают HTTP-запросы (никаких `Dio().get()` в виджетах).
* Запросы делает только `Repository`, который инжектируется через `RepositoryProvider`.
