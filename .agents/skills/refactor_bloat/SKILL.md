# Навык: Рефакторинг больших UI файлов (Refactor Bloat)

Этот навык применяется, когда размер файла превышает лимит в 250–300 строк, либо когда метод `build` становится слишком сложным и вложенным (God Object).

## Инструкция по выполнению

1. **Анализ файла:** Внимательно прочитай весь файл и определи логические независимые блоки UI (например, шапка, боковое меню, карточка товара, форма).
2. **Создание подпапки:** Если в модуле еще нет папки `widgets/`, создай её рядом с `view/` (или внутри `view/widgets/`).
3. **Вынос компонентов и защита от овер-декомпозиции:** 
   - **Табу на файлы-карлики:** Запрещено создавать отдельные файлы размером менее 60 строк (например, выносить одну кнопку или стейт на 25 строк).
   - Если компонент используется только в одном файле и файл укладывается в 250–300 строк, оставляй его в текущем файле как приватный класс (`class _HeaderWidget extends StatelessWidget`).
   - Выноси в отдельные файлы в папку `widgets/` ТОЛЬКО те блоки, которые:
     1. Реально переиспользуются в других местах;
     2. Имеют собственное сложное состояние / контроллер;
     3. Необходимы, чтобы спасти родительский файл от превышения жесткого потолка в 300 строк.
4. **Обновление главного файла:** Замени вынесенные блоки в главном `build` методе на вызовы новых виджетов. Пробрось все необходимые параметры, коллбеки (callbacks) и стейты через конструкторы новых виджетов.
5. **Проверка инъекций:** Убедись, что все нужные BLoC или провайдеры корректно доступны в контексте новых виджетов.
6. **Очистка импортов:** Убедись, что импорты в главном файле обновлены (импортированы новые виджеты из `widgets/`).
