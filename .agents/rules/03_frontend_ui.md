# v2 — стандарты под Google Antigravity 2 и мультиагентную среду

## 1. Архитектура и Структура (Feature-Driven)
- **Macro-Architecture:** Каждый модуль живет строго в `lib/features/<имя_модуля>`.
- **Внутреннее разделение:** `view/` (UI), `bloc/` (состояние), `repository/` (сеть/данные), `models/` (модели).
- **Справочники:** Перед началом верстки или изменения фичи **ОБЯЗАТЕЛЬНО** сверяйся с `frontend/ARCHITECTURE_MAP.md` и дизайн-токенами в `DESIGN.md`.

---

## 2. Управление состоянием (BLoC) и Сеть (Networking)
- **Запрет бизнес-логики в виджетах:** Запрещено использовать `StatefulWidget` для бизнес-логики и сетевых вызовов. Вся логика выносится в `BLoC` с пакетом `equatable`.
- **Изоляция перерисовок:**
  - Для списков, таблиц (10+ элементов) и полей ввода используй `BlocSelector<Bloc, State, T>` или `buildWhen: (prev, curr) => ...`.
  - Голый `BlocBuilder` на весь экран разрешен только для простых, редко обновляемых страниц.
- **[ИНВАРИАНТ] Трансформеры событий (Event Transformers):**
  - `restartable()` — по умолчанию для событий поиска, фильтрации и автокомплита (новый ввод отменяет предыдущий запрос).
  - `sequential()` — по умолчанию для событий, изменяющих данные (оплата, списание, кассовая смена, сохранение форм).
  - `droppable()` — для действий, где повторный клик должен игнорироваться (например, защита от дабл-клика по кнопке отправки).
  - *Отступление от дефолта обязано быть обосновано комментарием `[ИНВАРИАНТ]`.*
- **Жизненный цикл контроллеров:** Любой `TextEditingController`, `FocusNode`, `AnimationController`, `ScrollController` обязан быть явно освобожден через `.dispose()` — включая случаи хранения контроллеров внутри data-классов строк таблиц.
- **Сетевой слой:** UI и BLoC никогда не делают прямые HTTP-запросы (никаких `Dio().get()` в виджетах). Запросы выполняет только `Repository`, инжектируемый через `RepositoryProvider`.

## 3. Баланс связности и лимиты файлов (Micro-Architecture)
- **Лимиты строк:** Базовые ориентиры — см. `01_general.md §4` (200–250 / 300 / до 350).
- **Принцип связности (Locality of Behavior):** Связанные BLoC (с эвентами/стейтами) и зависимые формы имеют право занимать до 300–350 строк, если их разделение разрушает контекст.
- **Табу на файлы-карлики в UI:** Строго запрещено создавать отдельные файлы размером менее 60 строк для вспомогательных UI-виджетов одного экрана. Приватные вспомогательные виджеты должны жить в конце родительского файла.
- **[ИНВАРИАНТ] Автономия доменных моделей:** Чистые Enums, Value Objects, DTO и доменные контракты (в папках `models/`, `enums/`, `domain/`) имеют полное право быть компактными (<60 строк). Запрещено искусственно сшивать их с чужими классами ради набивки строк.
- **Критерий выноса в отдельный файл:** ТОЛЬКО если:
  1. Компонент переиспользуется в 2+ местах;
  2. У компонента собственный независимый жизненный цикл/контроллер;
  3. Выделяется самостоятельная доменная бизнес-логика (калькуляторы, валидаторы);
  4. Файл естественным образом превышает жесткий потолок в 300 строк.
- **[ИНВАРИАНТ] Тай-брейкер для выноса:** Если вынос по критерию 2 даёт файл короче 60 строк — **не выносить в отдельный файл**, а оставить как приватный класс (`class _PrivateHelperWidget extends StatelessWidget`) в конце родительского файла.

## 4. UI Kit & Дизайн-система (Строгий закон)
- **Запрет сырых кнопок:** Запрещено использовать `ElevatedButton`, `TextButton`, `OutlinedButton`. Использовать только компоненты дизайн-системы: `AppPrimaryButton`, `AppSecondaryButton`, `AppGhostButton`, `AppDangerButton`, `AppMenuButton`.
- **Соотношение со шкалой отступов:** Шкала размеров компонентов (`AppButtonSize`, `AppNavTileSize`) — самостоятельный масштаб высоты интерактивных элементов, независимый от 8px-сетки отступов. Значения 28/36/44/52px являются высотой компонентов и не подставляются как `padding`/`margin`.
- **Шкала размеров кнопок (`AppButtonSize`):**
  - `XS (28px)`: микро-действия в ячейках таблиц и бейджах.
  - `SM (32px)`: компактные кнопки в сайдбарах и строках.
  - `MD (36px)`: **стандарт для панелей инструментов (тулбаров), шапок страниц и кнопки `+ Добавить`**.
  - `LG (44-48px)`: **стандарт для диалогов, модальных окон и главных форм**.
  - `XL (52px)`: **стандарт для сенсорного POS-экрана и быстрой кассы**.
- **Шкала навигации (`AppNavTileSize` / `AppNavTile`):**
  - `SM (32px)`: вложенные папки, глубокие деревья сырья, компактные фильтры.
  - `MD (36-40px)`: **стандарт для полок склада, категорий каталога, списков техкарт**.
  - `LG (48-52px)`: **стандарт для главного сайдбара и разделов настроек**.
- **Закон контраста активных элементов:**
  - Кнопки действий (`AppPrimaryButton`): 100% сплошная заливка бренда + **Белый текст** в обеих темах.
  - Элементы навигации (`AppNavTile`): 12% мягкий фон + **Белый текст в Тёмной теме** (для максимальной резкости) / **Цветной текст в Светлой теме** (без тяжелых темных пятен).
- **Запрет хардкода цветов и стилей:** Запрещено использовать `Colors.*` и сырые `Color(0x...)`. Все цвета берутся только из `AppColors.*`, скругления из `AppRadii.*`, шрифты из `AppTextStyles.*`, тени из `AppShadows.*`.
- **Двухуровневый стандарт модальных окон (Two-Tier Dialog Architecture):**
  - **Tier 1 — `AppDialog` (Компактный стандарт, 440–480px, `mainAxisSize: min`):**
    Официальный эталон для всех компактных форм создания/редактирования (сотрудники, категории, ингредиенты, PIN-коды, отмена чеков, настройки). Естественная высота контента (`wrap-content`), гармоничная акцентная иконка, бесшовный футер с кнопками `AppGhostButton` и `AppPrimaryButton`.
  - **Tier 2 — `AppDialogScaffold` (Документный стандарт, 720–1080px):**
    Используется исключительно для сложных складских накладных и ревизий с длинными таблицами спецификаций, требующих фиксированной высоты и отдельной панели итогов.
  - **Запрет самописных `Dialog` с нуля:** Запрещено вручную верстать модальные окна через голый `Dialog(...)`. Использовать компоненты дизайн-системы.

## 5. Стандарты Арт-директора: Брендинг, Токены и Сетка
- **Цветовые палитры (Runtime-токены):**
  Токены `AppColors.brandPrimary` / `brandSecondary` динамически меняются в зависимости от палитры темы (`app_colors.dart`, метод `applyPalette()`):
  - **`ember`** — Amber/Gold + Warm Coral + Teal Mint.
  - **`cream`** — Тёплый амбер на кремовом / тёмно-эспрессо фоне.
  - **`ocean`** — Sapphire / Sky Cobalt Blue (палитра по умолчанию).
  *Никогда не хардкодь HEX под одну палитру — всегда используй имена токенов.*
  При изменении HEX любого токена палитры — обязана быть подтверждена контрастность (WCAG AA, 4.5:1) для фона и текста.
- **Типографика:**
  - `Space Grotesk` (`w600`, `w700`): заголовки экранов, крупные цифры выручки, акцентные кнопки.
  - `Inter` (`w400`, `w500`): основной текст, таблицы, списки, описания.
  - `JetBrains Mono`: номера чеков, артикулы, цены в каталоге, код.
- **8-пиксельная сетка (Grid & Spacing):**
  - Допустимые отступы: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64`.
  - Запрещены случайные значения (`padding: EdgeInsets.all(15)` или `height: 27`).
- **Скругления (Border Radius):**
  - Карточки: `16px` (`AppRadii.card`).
  - Кнопки и инпуты: `8-10px` (`AppRadii.button`, `AppRadii.inputRadius`).
  - Пилюли и бейджи: `24px` (`AppRadii.pill`).
- **Тени и Стекломорфизм:**
  - Мягкие глубокие тени с низкой непрозрачностью (5–10%), тени цветных кнопок подсвечиваются цветом токена с альфой `0.25-0.35`.
  - При `BackdropFilter` обязательно добавлять границу `1px` (`AppColors.glassBorder`). Не перегружать блюрами сенсорный POS-экран.

## 6. Микро-анимации и Интерактивность (Motion & Polish)
- **Hover & Touch:** Карточки и кнопки обязаны реагировать на курсор/нажатие:
  - Плавное увеличение: `AnimatedScale(scale: 1.02, duration: 200ms)`.
  - Премиальные кривые: `Curves.easeOutCubic`, `Curves.easeOutBack` (запрещены сырые линейные анимации).
- **Скелетоны вместо заглушек:** Загрузка данных — элегантные шиммеры/скелетоны вместо `CircularProgressIndicator`.
- **Никаких `Placeholder()`** в готовом коде.
- **Доступность (WCAG AA):** Контраст текста к фону не менее 4.5:1.

## 7. Тестирование Фронтенда
- **[ИНВАРИАНТ]** Любой BLoC, реализующий бизнес-логику (не чистый UI-стейт), обязан иметь unit-тест на основной сценарий и на минимум один edge-case (ошибка сети, пустой список) до мержа.
- **Фреймворк:** `flutter_test` + `bloc_test`. Виджет-тесты — для форм с валидацией и для компонентов, отмеченных `[ИНВАРИАНТ]` в докстринге.
