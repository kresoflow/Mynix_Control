# Kreso Flow - Global Rules

Эти правила являются абсолютным фундаментом архитектуры. Их нарушение недопустимо.

## 1. Backend (FastAPI, Python)
- **Multi-Tenancy:** Никогда не добавляй колонку `tenant_id` в модели. Изоляция тенантов работает на уровне схем PostgreSQL. Всегда используй зависимость `get_tenant_session`, которая устанавливает `search_path`.
- **PBAC (Access Control):** Защищай каждый эндпоинт в `router.py` зависимостью `require_permission('domain:action')`.
- **Separation of Concerns:** 
  - `routers/` — только маппинг HTTP, Pydantic-схемы и внедрение зависимостей.
  - `services/` — вся бизнес-логика и выполнение SQL-запросов. Логика должна быть разбита на доменные файлы (например, `menu_service.py`).
- **Micro-Architecture:** Лимит строк файлов (роутеры и сервисы) — 200–250 строк, жесткий потолок — 300 строк. Избегайте "God Objects". Декомпозиция сервисов выполняется строго по доменным сущностям, а не механическим распилом единых транзакций.
- **SQLModel/SQLAlchemy:** Используй асинхронный драйвер (`asyncpg`). Выполняй запросы через `session.exec()`.

## 2. Frontend (Flutter, Dart) & UI Kit
- **Macro-Architecture:** Строгое использование Feature-Driven Architecture. Каждый модуль живет в `lib/features/<имя_модуля>`.
- **UI Kit & Design System (Строгий закон!):**
  - **Запрет сырых кнопок:** Запрещено использовать `ElevatedButton`, `TextButton`, `OutlinedButton`. Использовать только компоненты дизайн-системы: `AppPrimaryButton`, `AppSecondaryButton`, `AppGhostButton`, `AppDangerButton`, `AppMenuButton`.
  - **Шкала размеров кнопок (`AppButtonSize`):**
    - `XS (28px)` — микро-действия в ячейках таблиц.
    - `SM (32px)` — компактные кнопки в сайдбарах и строках.
    - `MD (36px)` — **стандарт для панелей инструментов (тулбаров), шапок страниц и кнопки `+ Добавить`**.
    - `LG (44-48px)` — **стандарт для модальных окон, диалогов и главных форм**.
    - `XL (52px)` — **стандарт для сенсорного POS-экрана**.
  - **Шкала списков и деревьев навигации (`AppNavTileSize` / `AppNavTile`):**
    - `SM (32px)` — вложенные папки, глубокие деревья сырья, компактные фильтры.
    - `MD (38-40px)` — **стандарт для полок склада, категорий каталога, списков техкарт**.
    - `LG (48-52px)` — **стандарт для главного сайдбара и разделов настроек**.
  - **Закон контраста активных элементов:**
    - Кнопки действий (`AppPrimaryButton`): 100% сплошная заливка + **Белый текст** в обеих темах.
    - Элементы навигации (`AppNavTile`): 12% мягкий фон + **Белый текст в Тёмной теме** (для 100% резкости) / **Цветной текст в Светлой теме** (без тяжелых темных пятен).
  - **Запрет хардкода цветов и стилей:** Запрещено использовать `Colors.*` и сырые `Color(0x...)` в коде виджетов. Все цвета берутся только из `AppColors.*`, скругления из `AppRadii.*`, шрифты из `AppTextStyles.*`.
- **State Management:** Запрещено использовать `StatefulWidget` для бизнес-логики. Все состояния управляются исключительно через `BLoC` + `Equatable`.
- **Networking:** Прямые HTTP-запросы из UI или BLoC запрещены. Используй слой Repository (`Dio`), который инжектируется через `RepositoryProvider`.
- **Micro-Architecture (Баланс связности и декомпозиции):**
  - **Лимит строк:** Целевой ориентир — 200–250 строк, жесткий потолок — 300 строк.
  - **Принцип связности (Locality of Behavior > Line Count):** Запрещен слепой механический распил кода. Связные сущности (BLoC со своими эвентами и стейтами, атомарные транзакции склада, связанные формы) имеют право занимать до 300–350 строк, если их разделение разрушает контекст и целостность логики.
  - **Табу на файлы-карлики:** Строго запрещено создавать файлы размером менее 60 строк (например, выносить стейты на 20 строк или ячейку на 30 строк). Вспомогательные приватные классы (`class _SectionHeader extends StatelessWidget`) должны жить в конце родительского файла.
  - **Правило выноса компонентов:** Код выносится в отдельный файл ТОЛЬКО если:
    1. Компонент реально переиспользуется в 2+ местах;
    2. У компонента есть собственный независимый жизненный цикл или контроллер;
    3. Выделяется самостоятельная доменная бизнес-логика (калькулятор цен, валидатор данных);
    4. Файл естественным образом превышает жесткий потолок в 300 строк.

## 4. Стандарт комментирования и эстетики кода (Elite Documentation Standard)
- **Языковое разделение:**
  - Код, названия переменных, функций, классов, методов, роутов и коммиты — **строго на английском** (`calculate_total`, `ProcessOrderUseCase`).
  - Все комментарии, docstrings, объяснения бизнес-логики и пользовательский интерфейс (UI) — **строго на русском языке**.
- **Шапка файла (File Header):** Каждый ключевой файл начинается с аккуратной симметричной шапки:
  - Python: `# ==============================================================================`
  - Dart: `// ==============================================================================`
- **Сетка разделителей (80-Character Grid):** Логические секции внутри файла разделяются линиями шириной ровно до 80 символов:
  - Python: `# ─── 1. Название секции ──────────────────────────────────────────────────`
  - Dart: `// ─── 1. Название секции ──────────────────────────────────────────────────`
- **Семантические бейджи ответственности:**
  - `[ИНВАРИАНТ]` — бизнес-правила, которые нельзя нарушать (остатки, формулы цен, статусы документов).
  - `[ТРАНЗАКЦИЯ]` — атомарные операции с базой данных (commit / rollback, синхронизация списаний).
  - `[БЕЗОПАСНОСТЬ]` — проверка прав доступа (PBAC) и изоляция схем тенантов (`search_path`).
  - `[UI-KIT]` — токены дизайн-системы (`AppButtonSize`, `AppColors`, `AppRadii`).
- **Формула Docstrings:** Краткое назначение ➔ ключевой инвариант / бизнес-правило.
- **Запрет мусора:** Запрещены очевидные «капитанские» комментарии и любой закомментированный мёртвый код.
