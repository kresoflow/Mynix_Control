ТЕХНИЧЕСКИЙ СТЕК И ЖЕЛЕЗНЫЕ АРХИТЕКТУРНЫЕ ПРАВИЛА (MYNIX BACKEND RULES)
════════════════════════════════════════════════════════════════════════════════
1. Multi-Tenancy (Изоляция схем PostgreSQL):
   - Изоляция данных работает СТРОГО на уровне PostgreSQL схем через `search_path`.
   - ЗАПРЕЩЕНО добавлять колонку `tenant_id` в модели данных тенанта (за исключением глобальных таблиц `public.tenants`, `public.users`).
   - Каждый эндпоинт тенанта ОБЯЗАН использовать зависимость `get_tenant_session`, выставляющую `SET search_path TO "<schema>"`.

2. PBAC (Policy-Based Access Control):
   - 100% приватных эндпоинтов должны быть защищены зависимостью `Depends(require_permission('domain:action'))`.
   - Никаких скрытых или незащищенных эндпоинтов.

3. Separation of Concerns (Разделение слоев):
   - `routers/` — ТОЛЬКО HTTP-маппинг, валидация входящих Pydantic-схем, статус-коды и внедрение зависимостей (`Depends`). В роутерах ЗАПРЕЩЕНО писать SQL-запросы, расчеты и бизнес-логику.
   - `services/` — ВСЯ бизнес-логика, транзакции, списания, расчеты и вызовы `session.exec()`.
   - `models/` — SQLModel таблицы и Pydantic-схемы ввода/вывода (Create, Read, Update).

4. Micro-Architecture & Clean Code:
   - Жесткий лимит строк: не более 250–300 строк на файл (как для роутеров, так и для сервисов).
   - Запрещены God-классы и God-модули. Крупные сервисы разбивать на доменные части.

5. Async Event Loop Safety & Performance:
   - Полный запрет блокирующего синхронного I/O в async функциях (`time.sleep`, `open()`, `requests.get`, `urllib`).
   - Исключение проблем N+1 запросов: использование `selectinload` / `joinedload` для связей.
   - Использование `asyncpg` и асинхронных генераторов сессий.

6. Безопасность и Валидация (OWASP Top 10):
   - Отсутствие SQL-инъекций (запрет конкатенации строк и f-string в raw SQL без параметров).
   - Хранение паролей и PIN только через безопасные хеши (bcrypt/argon2).
   - Отсутствие утечек данных между тенантами (IDOR).
   - Иерархия кастомных ошибок `AppException` вместо 500 Internal Server Error и "слепых" `except Exception: pass`.

## 🔍 Чек-лист проверки модулей бэкенда

### 1. Модуль Авторизации и Пользователей (`app/users/`)
- [ ] Хранение паролей и PIN-кодов (хэширование bcrypt).
- [ ] JWT токены: валидация срока жизни (`exp`), извлечение `tenant_id` и прав.
- [ ] Иерархия ролей (Owner vs Staff).
- [ ] Эндпоинт смены пароля / профиля: валидация старого пароля.

### 2. Модуль Кассы и Заказов (`app/pos/`)
- [ ] Открытие и закрытие смены (`Shift`): корректность фиксации `opening_cash`, `closing_cash`, `discrepancy`.
- [ ] Создание заказа (`Order`): атомарность транзакции (создание заказа + списание ингредиентов + начисление бонусов + чек).
- [ ] Смешанная оплата (Split Payment: нал + безнал + бонусы + долг).
- [ ] Отмена и возврат чека: возврат списанных ингредиентов на склад.

### 3. Модуль Склада и Производства (`app/inventory/`)
- [ ] Рекурсивное списание многоуровневых техкарт (Блюдо ➔ Полуфабрикат ➔ Сырье).
- [ ] Накладные (`InventoryDocument`): пересчет себестоимости (`cost_per_unit`) методом средневзвешенной цены.
- [ ] Взаиморасчеты с поставщиками: автоматическое изменение баланса поставщика при статусах `unpaid`, `partial`, `paid`.
- [ ] Акты списания, оприходования и инвентаризации.

### 4. Модуль CRM и Лояльности (`app/crm/`)
- [ ] Баланс клиента (Сальдо / Депозит / Кредитный лимит).
- [ ] Начисление и списание бонусов (защита от двойного списания при конкурентных запросах).
- [ ] Журнал транзакций клиента (`CustomerTransaction`).

### 5. Модуль Аналитики (`app/analytics/`)
- [ ] Оптимизация SQL-агрегаций (отсутствие загрузки 10 000 строк в память Python для подсчета суммы).
- [ ] Группировка по дням, часам, категориям и официантам.

### 6. Модуль Кухни и WebSockets (`app/kitchen/`)
- [ ] Аутентификация WebSocket соединений через токен.
- [ ] Изоляция рассылки событий KDS по `tenant_id`.
- [ ] Очистка закрытых соединений и защита от утечки памяти.
